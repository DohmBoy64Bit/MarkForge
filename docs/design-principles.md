# Design Principles

## Functional Parity, Original Visual Identity

MarkForge uses MarkText as a functional audit target, not a visual template. The product should match practical editing capabilities where useful while developing its own interaction model, layout rhythm, iconography, theme language, and documentation voice.

## Calm, Dense, Professional

MarkForge is a writing and documentation tool. Its interface should stay calm and uncluttered, but it should not become sparse at the cost of repeated professional workflows. Toolbars, sidebars, status affordances, and command surfaces should be compact, predictable, and keyboard-friendly.

## Local-First Trust

The interface must make local operations feel dependable: clear file state, clear save state, explicit AI usage indicators, safe preview rendering, and no hidden network behavior.

## Extensible Without Feeling Experimental

Converters, templates, themes, and local LLM providers should feel like first-class product features. Users should not need to understand the internal package boundaries to use them.
